# Bridge Security

Requirement-to-enforcement mapping for the Bridge feature. See `docs/SECURITY_REVIEW.md` for the
site-wide baseline this extends.

| Requirement                         | Enforcement                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Never trust client calldata         | `src/lib/bridge/requestSchemas.ts` has no `to`/`data`/`value`/`feeBps`/`treasury`/`apiKey` fields at all — nothing to strip because there's no slot for the browser to supply them. `transactionRequest` only ever comes from a Zod-parsed provider response inside `normalize.ts`.                                             |
| Allowlist provider domains          | `src/lib/bridge/allowlist.ts#assertAllowedHost()` checked before every adapter fetch — hardcoded known hosts (`li.quest`, `api.relay.link`, `app.across.to`, `backend.gas.zip`), so a mistyped or hostile base-URL override can't redirect bridge traffic.                                                                      |
| Allowlist provider contracts        | Structural: `transactionRequest.to`/`approvalTarget` only ever come from the provider's own response, and `transactionRequest.chainId` must match the requested source chain (`chain_mismatch` otherwise). Optional extra pinning via `BRIDGE_CONTRACT_ALLOWLIST` (empty by default — never pre-filled with guessed addresses). |
| Prevent double fee collection       | `src/lib/bridge/fee.ts#checkPlatformFee` — see `docs/BRIDGE_FEE_MODEL.md`.                                                                                                                                                                                                                                                      |
| Prevent duplicate submission        | `useBridgeExecution` tracks submitted `routeId`s in a ref and refuses a repeat; the confirm button is disabled while pending/confirming.                                                                                                                                                                                        |
| Prevent stale quote execution       | `meta.expiresAt` (min of the provider's own expiry and the app's TTL) checked both server-side (`validateBridgeQuote`, at quote time) and client-side (`BridgeConfirmDialog`, at confirm time).                                                                                                                                 |
| Prevent unsupported-chain execution | `adaptersSupportingRoute()` in `registry.server.ts` gates every adapter's cached chain/token lists **before** any `getQuote()` call — an adapter that doesn't list both chains and both tokens is never quoted. Plus explicit `chainId` on every wagmi signing call.                                                            |
| Exact approval only                 | `useBridgeApproval` calls `approve(spender, BigInt(quote.inputAmount))` — never `maxUint256`. Spender comes only from the validated quote's `approvalTarget`.                                                                                                                                                                   |
| All keys server-side                | Every adapter is `.server.ts`; only `VITE_BRIDGE_ENABLED` is client-exposed.                                                                                                                                                                                                                                                    |
| Rate limiting                       | `guard(request, "bridge-quote", 30, 60_000)` — tighter than the 90/min default since one allowed request fans out to up to four paid upstream APIs. Separate buckets for `bridge-chains`, `bridge-tokens`, `bridge-status`, `bridge-analytics`.                                                                                 |
| Recipient verification              | `validateBridgeQuote` compares the provider's echoed recipient (`meta.recipientEchoed`, when supplied) against the request; a mismatch is rejected. When a provider doesn't echo one, it's `null` and the UI states the recipient couldn't be verified — never assumed correct.                                                 |
| Custom recipient warning            | `RecipientAddressInput` shows a persistent warning plus a required acknowledgement checkbox whenever the recipient differs from the connected wallet; `BridgeConfirmDialog` repeats the warning before the final confirm.                                                                                                       |

## Known limitation

`src/lib/market/http.server.ts`'s rate limiter is a plain in-memory `Map` — not coordinated
across serverless isolates. Already a documented, accepted limitation elsewhere in this codebase;
it matters slightly more here because each allowed `/api/bridge/quote` request fans out to
multiple paid upstream APIs. Mitigated by the tighter 30/min bucket, not solved.
